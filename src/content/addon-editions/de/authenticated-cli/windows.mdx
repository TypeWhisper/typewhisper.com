## Verfügbarkeit

Authenticated Provider CLIs 1.3.5 ist als [Plugin-Release für TypeWhisper unter Windows](https://github.com/TypeWhisper/typewhisper-win/releases/tag/plugin-authenticated-cli-v1.3.5) verfügbar und benötigt **TypeWhisper 1.1.0 oder neuer**. Der aktuelle Quellcode wird im `main`-Branch des Repositories gepflegt.

## Einrichtung unter Windows

1. Installiere Codex CLI, Claude Code CLI oder OpenCode CLI und melde dich über die CLI selbst an. OpenCode muss eine bestehende Anmeldung bei **OpenCode Zen** auflisten.
2. Öffne in TypeWhisper **Einstellungen > Plugins entdecken** und installiere **Authenticated Provider CLIs**. Das Add-on erscheint danach in der Seitenleiste der Einstellungen, und seine Seite öffnet sich.
3. Wähle unter **CLI-Profile** das Profil für deine CLI. Das Add-on beginnt mit je einem Profil für Codex CLI, Claude Code CLI, Antigravity CLI und OpenCode Zen.
4. Lass **Programmpfad** für die automatische Erkennung leer. Findet Windows mehrere Installationen, wähle den Pfad der nativen `.exe` aus oder gib ihn ein.
5. Wähle **Modelle aktualisieren**. Das Add-on prüft Version, Sicherheitsfunktionen und Anmeldung der CLI und lädt die Modelle dieser Sitzung.
6. Wähle ein **Modell** und dann **Profil speichern**.
7. Wähle das Profil als LLM-Anbieter in einem Workflow. Workflows zeigen es unter seinem Profilnamen an.

Unterstützt werden nur native `.exe`-Installationen. TypeWhisper lehnt abgemeldete, inkompatible, mehrdeutige oder nicht ausreichend isolierte Installationen ab, anstatt sie mit schwächeren Schutzvorkehrungen zu starten.

## Anbieter und Verfügbarkeit

| Anbieter        | Programmdatei  | Wann er verfügbar wird                                                                                                                                                                |
| --------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex CLI       | `codex.exe`    | Installiert, angemeldet und alle benötigten Isolationsfunktionen werden unterstützt                                                                                                   |
| Claude Code CLI | `claude.exe`   | Installiert, angemeldet und ein sicherer nicht interaktiver Modus wird unterstützt                                                                                                    |
| OpenCode Zen    | `opencode.exe` | Installiert, `opencode auth list` enthält OpenCode Zen, alle benötigten Isolationsfunktionen werden unterstützt und mindestens ein aktuelles Zen-Textmodell ist vollständig kostenlos |
| Antigravity CLI | `agy.exe`      | Nicht für Workflows verfügbar: Die CLI kann Tools und Projektkontext nicht isolieren                                                                                                   |

Das Add-on prüft den Status aller Profile alle fünf Minuten erneut, außerdem vor einer Anfrage, wenn die letzte Prüfung älter als sechs Minuten ist.

## Profileinstellungen

| Einstellung | Was sie steuert |
| --- | --- |
| **CLI-Profile** | Ein Eintrag pro CLI-Konfiguration. **+** fügt ein Profil hinzu; **Dieses Profil entfernen** löscht das ausgewählte, wenn es mehr als eines gibt. Workflows, die ein entferntes Profil nutzen, brauchen danach einen anderen Anbieter. |
| **Profilname** | Der Name in der Anbieterauswahl der Workflows. |
| **CLI** | Codex CLI, Claude Code CLI, Antigravity CLI oder OpenCode Zen. Du kannst mehrere Profile für dieselbe CLI hinzufügen. |
| **Umgebungsvariablen** | Optional, eine Zeile pro `NAME=WERT`, um ein anderes Sitzungsverzeichnis zu nutzen: `CODEX_HOME` für Codex, `CLAUDE_CONFIG_DIR` für Claude, `XDG_DATA_HOME` für OpenCode. Die Werte müssen vorhandene absolute lokale Ordner sein. Leer übernimmt die normale Sitzung der CLI. |
| **Programmpfad** | Leer für die automatische Erkennung in `PATH` und den Standard-Installationsorten, auch bei npm-Installationen von OpenCode, oder der Pfad einer nativen `.exe`. Skript-Shims werden nicht ausgeführt. |
| **Modell** | Codex: **Provider-Standard** oder ein Modell, das die installierte CLI meldet. Claude: **Provider-Standard** oder die CLI-Aliase Sonnet, Opus und Haiku; die Verfügbarkeit hängt von der Sitzung ab. OpenCode: nur Zen-Textmodelle, die derzeit vollständig kostenlos sind. Ein im Workflow gesetztes Modell hat Vorrang. |
| **Modelle aktualisieren** | Prüft die eingegebene CLI-Sitzung und lädt ihre Modelle, ohne zu speichern. |
| **Profil speichern** | Speichert das Profil zusammen mit der aktualisierten Modellliste. |

Für OpenCode lädt das Add-on die `opencode/*`-Textmodelle über `opencode.exe models opencode --verbose --pure` und bietet nur Modelle an, deren vollständiges Preisobjekt Werte für Ein- und Ausgabe enthält und bei denen jeder Zahlenwert einschließlich Cache- und Staffelpreisen null ist. Kostenlose Angebote können sich jederzeit ändern oder enden. Bei einer fehlgeschlagenen Aktualisierung bleibt die zuletzt geprüfte Liste des Profils erhalten; das Add-on weicht jedoch niemals auf ein ungeprüftes oder kostenpflichtiges Modell aus.

## Isolation und Datenschutz

Nur die Workflow-Anweisung und das Transkript beziehungsweise der ausgewählte Eingabetext werden an die Provider-CLI übergeben. Audio, CLI-Anmeldedaten, weitere TypeWhisper-Daten, Tools, Projektregeln und frühere Sitzungen sind nicht enthalten.

Codex läuft sitzungslos in einer schreibgeschützten Sandbox ohne Benutzerkonfiguration und Regeln; Freigaben, Tools, Websuche, Projektanweisungen, Memories und Multi-Agent-Funktionen sind deaktiviert. Claude Code läuft im sicheren Modus für genau einen Durchgang ohne integrierte Tools, MCP-Tools, Browserzugriff, Slash-Befehle oder Sitzungsspeicherung. Jede Anfrage nutzt ein isoliertes temporäres Verzeichnis sowie Zeit- und Größenlimits.

OpenCode verwendet die bestehende Zen-Anmeldung aus seinem Datenverzeichnis weiter, TypeWhisper liest oder speichert die Zugangsdaten jedoch nicht. Jede Anfrage erhält eigene temporäre Pfade für Konfiguration, Cache, Status und Datenbank. Projekt- und Benutzerkonfiguration, benutzerdefinierte Agents, Befehle, Plugins, MCP-Server, Sitzungen, Freigaben, Snapshots und Update-Prüfungen sind deaktiviert; Tool-Berechtigungen werden vollständig verweigert. OpenCode muss ein streng strukturiertes Textergebnis zurückgeben und kann keine frühere Sitzung fortsetzen.

Das Anbieterkonto verarbeitet den Prompt weiterhin über seinen Cloud-Dienst. Dabei können eigene Tarif-, Nutzungslimit- und Datenschutzregeln gelten. Bei einigen kostenlosen OpenCode-Zen-Modellen dürfen Prompts und Antworten für das Training verwendet werden. Prüfe die [aktuellen Zen-Preise und Datenschutzbedingungen](https://opencode.ai/docs/zen/) des gewählten Modells und sende keine persönlichen oder vertraulichen Texte, sofern diese Bedingungen es nicht erlauben.
